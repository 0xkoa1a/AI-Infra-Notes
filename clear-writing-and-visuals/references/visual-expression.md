# 图示表达与设计语言

新增、修改或 Review 图表时使用本文件。图的首要作用是降低理解关系的成本。

## 先决定这张图回答什么

在设计前，用一句内部说明明确读者应从图中看懂的关系，例如“哪些状态在阶段切换后继续更新”“两种方案在哪个条件下分叉”“数据所有权如何转移”。这句话用于约束设计，不必机械地显示在成品上。

如果文字已经能短而清楚地解释单个事实或简单动作，直接使用文字。如果精确对照是主要任务，优先使用表格。交互只有在切换对象、阶段、尺度或查看细节能够改善理解时才使用。

| 表达任务 | 常用形式 | 重点 |
|---|---|---|
| 整体构成、主路径和分支 | 架构图或流程图 | 对象、接口、连接和关键阶段 |
| 局部机制、控制与数据依赖 | 模块图或依赖图 | 前提、分叉、汇合、反馈和状态更新 |
| 对象间的允许关系 | 矩阵或关系表 | 行列含义、关系变化和例外 |
| 数据分布或所有权变化 | 布局图 | 哪个对象持有什么，以及何时改变 |
| 精确差异与条件 | 比较表 | 一致的比较维度和完整条件 |
| 随时间的执行、等待与重叠 | 时间线 | 时间尺度、泳道含义和活动关系 |
| 数量、趋势与分布 | 常规统计图 | 单位、基准、范围和不确定性 |

优先使用目标环境已有的图示语言和组件。简单关系可用 Mermaid 或 SVG，需要状态切换时再采用适合宿主的交互组件；定量分析可以使用标准绘图工具。不绑定框架，不要求额外安装插件，也不预设每篇都新增图。

## 控制信息密度

总览图保留主路径、关键分支、输入输出和重要阶段。共用的局部加工规则集中解释；精确内部依赖放到相应模块图。不要在每条分支反复写相同的归一化、校验、转换等操作细节。

节点优先写对象或动作名称，再按需标关键接口。图中文字过密时，先检查重复、分组和解释任务，再调整布局。避免通过持续缩小字体容纳冗余内容。

连续阶段若持有相同数据范围，可合并重复布局，用箭头或操作标签保留变化过程。节点合并需要保留分支归属、输入输出和关键依赖。分支仍然独立时，用明确的连线或标注表达，避免合并图形让读者误以为状态已经混合。

形状和数字只标在支撑理解的位置。完整维度可以集中在表格，精确数值也可放在点击或悬浮详情；核心机制必须在默认视图中可读。

图下注释用于说明必要的图例、限定或结果。若注释和额外说明卡已经重复正文，应把解释放回合适的位置并减少图内负担。

## 统一视觉含义

优先继承已有配色、字体和组件，保持同一对象在不同图及切换状态中的识别方式一致。用色表达稳定的类别或角色，不因装饰需要随意更换；新材料可采用少量语义颜色，无需固定通用色号。

在同一视图内明确颜色编码的是对象、角色还是状态。若多个维度都需要表达，可结合泳道、位置、边框或文字，避免依赖颜色同时解释多件事。

箭头、虚线、边框和填充各自承担稳定含义。数据流、依赖、条件控制、缓存读取等确实需要区分时采用不同样式，并提供简短图例。标准化方向和对齐，让视线能沿主路径自然移动。

数量关系应由准确的坐标、长度、面积或标签表达。装饰性尺寸不应误导为数量比例；机制示意若容易被当成实测，需要明确说明。

## 状态切换

切换对象或阶段时，检查标题、图形、说明、数值、图例和详情是否同步。只适用于某个阶段的说明应跟随状态出现，通用说明应位于清楚的公共位置。

默认状态应能帮助读者建立认识，按钮名称说明比较的是哪个维度。使用真实可用的数据组合，缺失组合明确显示缺失原因。重要结论不应只能依赖悬浮才能发现。

例如，切换到“初次处理”后，图下仍显示“复用上次结果”的说明，会混淆当前行为与其他阶段。应将说明绑定当前状态，或将跨阶段规则移到正文集中解释。

## 定量图与时间线的忠实性

定量图标清单位、测量对象、统计口径和必要条件。区分实测、估算、示意和预测；比较使用可比范围与尺度。没有依据的数据保持缺失，不用其他对象或阶段的数据填补。

时间线横轴使用实际时间，泳道明确表示任务、队列、资源或其他执行单元。队列并行不自动意味着独占硬件资源。比较面板采用一致尺度，短操作不人为拉长。代表片段与整体统计承担不同作用，不将多个片段拼成一次虚构执行。

细碎活动按解释需要归并为有明确语义的阶段，默认不展示原始活动层。合并时保留影响判断的内部空隙、跨队列关系和关键依赖；不能把阶段起止跨度全部填成持续活动。按需区分阶段跨度与累计活动时长，重叠区间避免重复计数。

未被其他工作覆盖的活动、已确认的依赖等待、原因未明的空闲应采用准确标签。图上出现空洞本身不足以证明它可以消除；同一窗口在多个面板重复出现时，其时间或候选收益不能直接相加。

需要测量或实现核查才能解释图形时，先检查已授权范围内的材料；新增采集依主文件的范围规则处理。

## 正反例与验收

| 常见问题 | 调整方法 |
|---|---|
| 总览中每条分支重复相同的四行操作 | 保留分支与主要阶段，共性机制集中说明 |
| 连续六张小矩阵中有多组相同布局 | 合并相同持有范围，用操作标签保留过程 |
| 图中堆叠解释卡，内容与正文相同 | 保留有图形价值的关系，文字解释回到正文 |
| 所有对象都用不同颜色，但颜色没有稳定含义 | 确定编码维度，减少配色并保持跨图一致 |
| 小活动合并后把原有空隙全涂满 | 标清阶段范围，保留关键间隙或分别报告活动时长 |
| 交互图切换后图注仍属于上一状态 | 联动更新，或将确实通用的说明移到公共位置 |

在目标载体实际查看默认视图，检查文字、连线、表格与公式。验证相关切换及展开状态，确认可读、无溢出、含义一致，精确数值与底层数据相符。按任务要求确定设备和主题范围；不要将某个仓库的屏幕尺寸或构建命令固化为通用规范。

## 网页图示的实现注意事项

宿主使用 Vue/SVG 等组件时，优先复用组件和语义颜色。多区域布局、分组或局部放大也可以成为选用组件的理由，不必为采用组件而添加交互。不要为一次图示增加组件库或过早抽象通用绘图框架。

公式使用已有数学渲染方案或正确的上下标；避免在成品中直接显示源码记号。为 SVG 提供可访问名称，交互使用真实按钮，支持键盘操作并同步展开状态。图内标题不应意外进入文章目录。颜色配合标签、线型或区域表达含义。
