# Review 与修改后复查

本文件用于审阅说明性文档，以及执行修改后的整体复查。关注读者能否顺畅建立认识、理解机制和判断结论，覆盖篇幅、结构、详略、叙述、语言及图示。

## 确定审阅任务

沿用用户已经说明的用途、读者与关注点。一般 Review 请求先输出意见；用户要求执行、修订或已明确授权修改时，完成对应编辑。

先阅读全文和关键图表，建立对主线及信息分布的认识。图中文字、图注、折叠内容和交互状态都属于文档，必要时在实际页面查看。仅检查源文件时，应准确说明渲染尚未验证。

当关键解释涉及具体实现、性能结论或缺少支撑数据时，按主文件的核查范围规则处理。例如，将耗时下降归因于减少工作量时，先核对已有实现与测量，确认改变的是工作量还是等待。已有材料不足且进一步实验超出授权时，再说明缺口并询问；期间继续开展独立的内容与表达审阅。

区分阅读中已经确认的问题、对事实准确性的疑问和需要额外核查的事项。不要仅凭图形或措辞把机制推断成事实，也不要把尚未完成的核验表述为已通过。

## 审阅的六个方面

| 方面 | 关键判断 | 常见修改方向 |
|---|---|---|
| 篇幅与取舍 | 每项信息是否支撑主要观点？哪些解释重复？删减是否造成缺口？ | 合并冗余、补全关键机制，按价值决定正文或参考位置 |
| 整体结构 | 主要观点和全貌是否足够早出现？细节是否有定位？章节是否自然承接？ | 简化总览前移，重排前提与结论，调整章节分工 |
| 详略分配 | 关键差异是否集中？共性是否重复？基础与精确细节是否匹配读者？ | 比较表聚合差异，共性讲一次，精确补充按需折叠 |
| 叙述与语言 | 每段是否有明确观点？句间是否推进？因果是否完整？是否遵循语言指引？ | 补足推理，使用具体动词，减少套话、术语堆积和列表滥用 |
| 图文与视觉 | 每张图解决什么问题？是否重复正文？节点、注释和交互是否过载？ | 收窄图的任务，减少重复布局，移动解释，联动阶段说明 |
| 完整性与忠实性 | 条件、依赖和口径是否准确？简化是否改变含义？推测是否写成定论？ | 保留关键关系，明确证据状态，按范围完成必要核查 |

先处理妨碍整体理解、导致误读或影响结论的问题，再处理局部措辞和排版。重要程度由阅读影响决定，不必强行使用代码审查的缺陷等级或凑够固定数量的意见。

审阅也要识别有效内容。例如，解释输入和输出归属的一句话可能很关键，即使附近有重复文字也应保留。删减目标是减少负担，保留必要支撑。

## 如何判断图文冗余

为每张图概括其解释任务，再和相邻文字、表格及其他图比较。节点名称或关键数值的必要复现可以保留；同一规则在多个地方完整讲述，则需要重新分工。

常见情况是：总览图已经展开局部算子，后面又有模块图；矩阵上方、下方和正文三次解释相同的可见关系；布局未变的连续步骤重复绘制同一矩阵；大量说明卡让图成为另一篇文章。修改建议应说明保留哪种关系、移动哪段说明，而不是笼统要求“减少信息”。

交互图逐个检查与本次审阅有关的状态。尤其注意当前状态是否混入其他阶段的说明、缺失数据是否被默认值掩盖，以及简化后是否失去分支归属。

## 输出可执行的意见

先给出最影响阅读效果的判断，再说明具体位置、造成的影响和建议改法。引用足够定位的章节、原句、图名或文件位置。对复杂重组可以给出建议顺序；图示调整可以用短表列出其职责、冗余与处理方式。

| 笼统意见 | 可执行意见 |
|---|---|
| “结构不清楚。” | “完整流程图在多个局部概念之后出现，读者缺少定位。将简化总览前移，再把细节放回相应模块。” |
| “文字太多。” | “同一条缓存规则在正文、两张说明卡和图注中重复。正文解释成立条件，图中保留状态变化，图注只说明图例。” |
| “详略不当。” | “文档详细推导了辅助公式，却没有集中说明两个方案的适用条件。先补齐比较维度，将推导放入参考。” |
| “图太复杂。” | “四条分支重复列出共性处理，且文字已经溢出。保留分支和模块连接，共性流程由旁边的模块图解释。” |
| “这段不准确。” | “当前证据显示等待被覆盖，还不足以支持工作量减少。建议改为证据支持的表述，再按授权范围处理核查缺口。” |

对建议区分确定的问题和编辑选择。说明调整如何改善理解，避免把个人审美偏好描述成事实错误。若没有发现实质问题，直接说明检查范围和结果。

交付 Review 时优先保留值得行动的意见。无需逐项复述检查清单、罗列所有阅读过程或加一段重复总结。

## 执行修改与复查

用户要求执行后，以已确认的问题和目标为依据完成修改。重排时检查段落引用、概念引入顺序、章节衔接和术语一致性；移动到参考的内容仍应能独立核对。

图示减负时检查节点合并是否改变分支、顺序或依赖。说明卡移除后，正文应保留重要条件；交互状态调整后，说明、数值和图形应同步。

完成后重新连续阅读正文，确认读者无需在多个章节反复寻找前提。对照原 Review 检查问题是否解决，是否出现新的缺口、重复或歧义。再按语言参考逐段检查，并查看真实载体中的图表、公式和相关交互。

验证范围与改动相称。若修改了网站组件，遵循目标项目的文档检查、类型检查、现有测试和构建要求，查看实际渲染；纯文字任务采用相应的内容与排版检查。结果报告说明做过的检查和仍影响使用的限制，不将未执行的核查包含在“验证通过”中。

网站验证至少覆盖页面身份与正文、目录锚点、图示与公式边界、主要交互和运行时错误。设备与主题范围遵从用户要求及项目约定；用户明确免测时遵从，并如实报告实际覆盖范围。

复用现有浏览器能力和依赖；临时截图与检查脚本放在项目外，验证后按项目约定清理产物和预览服务。检查工作区改动，保留无关内容；已有错误与本次问题分开报告。只修改 skill 时校验其格式、引用和安装结果，无需运行无关的整站测试。
