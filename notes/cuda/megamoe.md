# DeepGEMM MegaMoE：沿四 GPU 跟完一次 MoE 前向

MegaMoE 将 Dispatch、专家计算与 Combine 放进常驻 GPU kernel。**每张卡既处理自己的源 token，也计算本卡专家收到的 token；不同线程持续推进搬运、矩阵计算和回传，用块级信号衔接。**

下文以 SM100 上的 FP8 激活路径为例，先跟随四张 GPU 上的数据移动，再进入其中一个专家的计算，最后解释多个块怎样交错推进。

## 初始分布：token 与专家分别在哪张卡

四张 GPU 各有两个源 token、两个专家。路由器已为每个 token 选择两个专家，即 top-k=2；两个选择按顺序记为路由槽 s0、s1。

<MegaMoEDiagram view="placement" />

专家计算使用所属 GPU 的权重，因此 token 的路由决定了输入需要到达哪张卡。例如 a0 的一个分支在 GPU 0 本地计算，另一个分支交给 GPU 1 的 E3。最终两份结果都要回到 a0 原来的位置。

## Symmem：用对应布局找到远端字段

每卡独立分配一段可供其他 GPU 访问的显存，称为 symmetric memory，简称 Symmem。各卡使用相同的字段布局，因此知道目标卡基址与字段偏移，就能定位远端输入、索引表或回传槽。

专家计算包含两次线性投影，后文分别称为 L1、L2；图中的 X 是原始输入，A 是两次投影之间的激活。每条路由还带一个权重 α，决定该专家对 token 输出的贡献。本路径采用 FP8 激活，scale 是配套的缩放系数，随激活一起保存和搬运。

<MegaMoEDiagram view="symmem" />

**输入位置与专家输入位置承担不同职责。** 源输入按原 token 顺序保存，供选中该 token 的专家读取；L1 输入环则按专家组织，使来自不同卡的 token 能组成同一专家的矩阵。来源记录为专家输入的每一行保留“源 GPU、源 token、路由槽”，用于后续回传。

## Dispatch：先建立索引，再由专家卡拉取输入

Dispatch 先让专家卡知道需要哪些输入，再把这些输入组织成连续行。图中可以切换步骤和 GPU，追踪任意一张卡的发送或接收过程。

<MegaMoEDiagram view="dispatch" />

**发布索引与计数。** 源卡将每条路由的 token 位置和路由槽写入目标卡的索引列表，列表按“本地专家、来源 GPU”分组。多个 CTA 通过原子计数领取不同的列表位置，避免写入冲突。各来源的列表与计数发布完成后，接收方就能确定每个专家有多少输入行，以及需要多少个计算块。

**由接收卡拉取。** 专家卡根据索引读取源 token 的 FP8 输入、scale，以及这条路由对应的 α。TMA 张量搬运机制先把输入片段从源卡显存送入接收卡的共享内存 SMEM，再写入本地 L1 输入环；来源记录与输入行对应保存。同一专家的不同来源会交错排列，后续计算使用这些行组成的矩阵。

**发布输入块就绪。** 一个 token 的全部输入片段和配套信息写完后，Dispatch 才更新该块的就绪计数。一个块容纳的行数记为 $B_M$；计算线程等整块输入准备好后读取。末块保留实际有效行数，并按块容量补齐存储位置。

后文跟踪 GPU 0 的 E0 输入块：有效行是 a0、c1，来源分别是 GPU 0 的槽 s0 与 GPU 2 的槽 s1。

## 一个输入块怎样经过两次投影

现在进入 E0 的本地计算。设专家 $e$ 收到 $m_e$ 行输入，隐藏宽度为 $H$，SwiGLU 后的中间宽度为 $F$。输入 $X_e$ 的形状是 $[m_e,H]$；两次投影的权重分别为 $W_{1,e}\in\mathbb{R}^{2F\times H}$、$W_{2,e}\in\mathbb{R}^{H\times F}$。

L1 为每行生成 gate 与 up 两组特征，分别记为 $G_e,U_e$，形状均为 $[m_e,F]$。SwiGLU 对 gate 执行 SiLU 后，与 up 逐元素相乘。按输入行顺序排列的路由权重组成列向量 $\boldsymbol{\alpha}_e\in\mathbb{R}^{m_e\times1}$，乘入中间激活 $A_e$ 后，再由 L2 投影回隐藏宽度，得到专家输出 $Z_e$：

$$
\begin{aligned}
[G_e,U_e]&=X_eW_{1,e}^{\mathsf T},\\
A_e&=\boldsymbol{\alpha}_e\odot\bigl(\operatorname{SiLU}(G_e)\odot U_e\bigr),\\
Z_e&=A_eW_{2,e}^{\mathsf T}.
\end{aligned}
$$

这里 $\operatorname{SiLU}(g)=g/(1+e^{-g})$，$\odot$ 表示逐元素相乘；每行的 α 沿 $F$ 个特征广播。L1 后处理将 $A_e$ 量化为 FP8，并生成新的 scale，供 L2 读取。这样，L2 写回的 $Z_e$ 已经包含路由权重。

### 从输入缓冲到矩阵计算

每项计算任务选择一个专家、一个 token 块和一组输出列，由同卡的一对 CTA 完成。调度、激活加载、权重加载、矩阵计算和后处理由不同 warp 负责，按相同任务顺序推进。

TMA 将显存中的激活和权重送入 SMEM；UMMA 是 Tensor Core 执行矩阵乘法的指令，累加结果保存在专用的 Tensor Memory（TMEM）中。后处理线程等累加完成后读取 TMEM，执行激活、量化或结果回传。

下图取 $B_M=64$、$H=512$、$F=256$，跟踪输出列组 $[0,256)$ 的一项任务。图中形状表示块容量，E0 的两条有效输入占块内两行，后处理只写有效行；沿输入特征轴每次读取 128 个特征。可切换 L1、L2，观察同一条硬件路径处理不同输入和输出。

<MegaMoEDiagram view="compute" />

一次任务会遍历完整输入特征轴：L1 遍历 $H$ 个特征，L2 遍历 $F$ 个特征。各输入片段先在 SMEM 中准备好，再参与同一输出块的累加；最后一个片段完成后，才通知后处理线程读取结果。

### 两个 CTA 怎样共同使用输入

同一批 token 的不同输出列都需要使用完整输入。两个 CTA 分别将一半输入行加载到自己的 SMEM，各自加载所负责输出列的权重，再由 leader 发射协作 UMMA。指令共同使用两边的激活，分别在两份 TMEM 中累加不同输出列。

### L1 写完哪些列，L2 就能读取哪些特征

L1 的输出列宽记为 $B_N=128$。其中包含 64 对 gate/up，经过 SwiGLU 后生成 64 个中间特征。L2 每次读取的输入特征宽度记为 $B_K=128$，因此**两个 L1 列块写完，才能提供一个 L2 输入特征块。**

<MegaMoEDiagram view="readiness" />

L1 后处理先将量化激活和 scale 写入 L2 输入环，等写入完成，再发布对应列块的就绪位。L2 加载线程等待当前输入特征块所需的位，以 acquire 语义确认数据可读；生产端的 release 与这个读取配对，保证数据写入先于消费。

## Combine：写回原 token 的路由槽，再本地求和

L2 后处理沿来源记录找到目标 GPU、token 和路由槽，将 BF16 结果片段写到对应位置。不同专家的贡献有各自的槽位，因此可以分别回传，由源卡完成最终求和。

<MegaMoEDiagram view="combine" />

**完成通知按专家卡汇总，读取按 token 的路由等待。** 一张卡先汇集本卡全部 L2 写回，再向各源卡发布本轮完成通知。源卡处理某个 token 时，等待它所选专家所在卡的通知，然后读取两个槽。跨 GPU 的 release/acquire 保证源卡观察到通知后，能够读到先前写回的结果。

设源卡编号为 $r$、token 位置为 $t$、隐藏特征位置为 $h$，$C_r[s,t,h]$ 表示该卡路由槽 $s$ 中的专家贡献。两个槽逐元素相加，得到输出：

$$
Y_r[t,h]=C_r[0,t,h]+C_r[1,t,h].
$$

各卡按原 token 顺序处理这些输出，使用 FP32 累加后写成 BF16。

## 多个块怎样持续推进

### 先派发 L1，再交错 L2 与 L1

L1 生产中间激活，L2 消费这些激活并发起结果回传。调度器先派发一批 L1 任务预热，再交错派发 L2 与 L1，使后续输入继续生成，并分散 L2 写回的发射。

<MegaMoEDiagram view="schedule" />

**生产任务已派发，与输入数据已写完，是两个不同条件。** 调度器先确认 L2 所需的 L1 生产任务已经派发，避免等待中的 L2 占住流水线，而生产它所需数据的任务仍无法进入。L2 的加载线程随后按当前输入特征块的就绪位等待数据。

### 环形槽何时可以覆盖

输入与中间激活按块保存在有限的环形缓冲中。设 $q$ 是逻辑块编号，$R$ 是每个环的物理槽数，则 $q$ 和 $q+R$ 使用同一物理槽 $q\bmod R$。就绪信号还带有轮次信息，使同一槽的新旧内容能够区分。

<MegaMoEDiagram view="ring" />

**两个环分别等待自己的消费者。** L1 输入槽在所有 L1 输出列任务发布对应中间结果后归还；L2 输入槽在所有 L2 输出列任务完成矩阵累加后归还。后者此时已把结果保存在 TMEM，后处理可以继续从 TMEM 读取。

来源记录按逻辑块单独保存，因此环内装入新激活后，旧结果仍能按旧记录写回。TMEM 又有自己的释放点：最后一次有效读取完成后，累加槽可供后续任务覆盖，已读入寄存器的结果继续转换和回传。

回传积压会拖慢后处理，延迟 TMEM 归还，再使后续矩阵计算等待。任务交错与缓冲复用围绕这些依赖推进，将输入生产、计算和回传衔接成持续运行的流水线。
