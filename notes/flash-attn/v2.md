# FlashAttention v2

FlashAttention v2 沿用 v1 的分块计算和 Online Softmax，通过减少逐元素计算、增加并行工作和减少 Warp 间通信，提高 GPU 的计算效率。本文接着 [v1](./v1.md) 介绍自注意力前向；输入仍为 $Q,K,V$，输出仍为 $O$，数学上计算相同的精确 Attention，主要计算复杂度仍为 $O(N^2d)$。

## v1 留下的性能问题

v1 已经避免了完整 Score 和概率矩阵在 HBM 中的读写，但减少 HBM 访问之后，执行这些计算的方式仍有优化空间。

理解这些问题需要区分两个分工层次：GPU 由多个 SM（流式多处理器）组成，Thread Block 被调度到某个 SM 上执行；一个 Thread Block 内又包含多个 Warp，每个 Warp 有 32 个线程。Tile 描述数据如何分块，Thread Block 和 Warp 描述线程如何组织，算法实现负责将数据块分配给这些线程。不同 Warp 可以通过 Shared Memory 交换数据，但读写中间结果和同步都需要时间。

Tensor Core 擅长矩阵乘，Softmax 和输出更新中的指数、除法、逐元素缩放则依赖其他执行单元。后者即使 FLOPs 占比小，也可能占用明显的执行时间。

在这里比较的第一版方案中，主要有三个问题：

- **每轮输出更新的计算较多。** 每处理一个 KV Tile，都要将已归一化的输出还原为加权和，更新后再归一化。这些逐元素操作会反复作用于整个输出 Tile。
- **Thread Block 数量可能不足。** 主要沿 Batch 和 Head 维度分配工作；Batch 和 Head 数较小时，即使序列很长，也可能有不少 SM 没有工作。
- **Block 内需要合并不同 Warp 的输出贡献。** 不同 Warp 分别处理一部分 Key/Value，却为同一组 Query 产生结果，需要通过 Shared Memory 汇总。

v2 分别调整了输出状态的表示、Thread Block 的任务划分和 Block 内的 Warp 分工。[作者介绍](https://princeton-nlp.github.io/flash-atttention-2/)

> 本文以原始 FlashAttention 论文的循环顺序和 FlashAttention-2 论文描述的第一版实现为比较基线。后续实现也吸收了这些优化，实际 kernel 的分工方式需要结合具体版本判断。

## 减少每轮输出更新的计算

沿用 v1 的记号：$m_i$ 是每个 Query Row 已见过的最大 Score，$l_i$ 是以该最大值为基准的累计指数和。v1 保存已归一化的输出 $O_i$，每轮先乘回旧分母，再在更新后除以新分母。

v2 改为保存未归一化的输出累加器 $A_i$。对第 $r$ 个 Query Row，它等于当前分母乘以归一化输出：

$$A_{i,r,:}=l_{i,r}O_{i,r,:}$$

这样，内层循环只需更新分子和分母，最终再执行一次除法。开始处理 KV 序列时，仍将 $m_i$ 初始化为 $-\infty$，$l_i$ 和 $A_i$ 初始化为零。

现在处理当前 Tile 的 Score $S_{ij}=Q_iK_j^\top/\sqrt d$。与 v1 相同，先得到新的逐行共同最大值，以及旧状态换到新基准的缩放系数：

$$m_i'=\max\bigl(m_i,\operatorname{rowmax}(S_{ij})\bigr),\qquad
\alpha_{ij}=\exp(m_i-m_i')$$

当前 Tile 的权重直接按这个共同最大值计算。对第 $r$ 行、第 $k$ 列：

$$\widetilde P_{ij,r,k}'=\exp(S_{ij,r,k}-m_{i,r}')$$

v1 先按当前 Tile 自己的最大值计算指数，再乘 $\beta_{ij}$ 换到共同基准；这里直接使用 $m_i'$，便省去了这次换算。旧状态仍需乘 $\alpha_{ij}$，使新旧贡献处于同一个指数尺度。

因此，新分母是缩放后的旧分母加上当前 Tile 的指数和；新累加器是缩放后的旧累加器加上当前 Tile 的 Value 加权和：

$$\begin{aligned}
l_{i,r}'&=\alpha_{ij,r}l_{i,r}+\sum_{k=1}^{B_c}\widetilde P_{ij,r,k}',\\
A_{i,r,:}'&=\alpha_{ij,r}A_{i,r,:}+(\widetilde P_{ij}'V_j)_{r,:}.
\end{aligned}$$

用 $m_i',l_i',A_i'$ 替换旧状态，继续处理下一个 KV Tile。全部处理完成后，才逐行归一化：

$$O_{i,r,:}=\frac{A_{i,r,:}}{l_{i,r}}$$

分子和分母始终使用同一个指数基准，因此推迟除法仍能得到完整 Attention 的结果。省下的是每轮对整个输出 Tile 的反复归一化；最大值变化时，对旧累加器的缩放仍然保留。[论文 §3.1.1、Algorithm 1](https://tridao.me/publications/flash2/flash2.pdf#page=5)

> 若前向还要为训练的反向计算保存 Softmax 统计量，v2 保存逐行的 $L_i=m_i+\log l_i$。前向迭代中仍使用 $m_i,l_i$；保存 $L_i$ 是为了后续重建所需的概率值。

## 将 Query Tile 分给不同 Thread Block

Attention 的每一行只需要自己的 Query 和该行能够关注的全部 Key/Value。因此，**不同 Query Tile 可以分别完成自己的全部输出，不需要合并彼此的结果**。

原始 v1 方案以 KV Tile 为外层循环：同一份 KV 读入片上后，依次服务多个 Query Tile；各 Query 的输出状态则在不同 KV 迭代之间读回、更新并写回 HBM。v2 交换两层循环，让一个 Thread Block 负责一个 Query Tile，在内部遍历 KV 序列：

```text
parallel for 每个 (Batch, Head, Q_i Tile)
    加载 Q_i
    初始化 A_i, m_i, l_i

    for 每个 K_j, V_j Tile
        加载 K_j, V_j
        计算 S_ij
        更新 A_i, m_i, l_i

    O_i = A_i / l_i
    写回 O_i
```

每个 Block 因而可以将 $Q_i$ 和 $A_i,m_i,l_i$ 保留在片上存储中，完成这个 Query Tile 后再写回输出。这里的片上存储包含寄存器和 Shared Memory；具体数据如何放置取决于 kernel 实现。

这同时增加了可调度的工作数量。设 Batch Size 为 $B$，Head 数为 $N_h$，序列长度为 $N$，每个 Query Tile 有 $B_r$ 行。Query Tile 数为 $T_r=\lceil N/B_r\rceil$，第一版方案主要提供 $BN_h$ 个 Thread Block，按 Query Tile 分工后则提供 $BN_hT_r$ 个。

例如，$B=1$、$N_h=8$、$N=4096$、$B_r=128$ 时，每个 Head 有 32 个 Query Tile，Thread Block 总数从 8 个增加到 256 个。原先只有少量 SM 能拿到工作，现在可以将不同 Query Tile 分给更多 SM。这是总任务数；同时驻留多少个 Block，还受 SM 数量、每个 Block 的寄存器和 Shared Memory 用量限制。

**KV 的复用也有取舍。** 从这两种循环可以看出，原来一个 Block 可以用同一份 KV 服务多个 Query Tile；现在不同 Query Block 都要读取所需的 KV。缓存可能让这些读取复用数据，实际 HBM 流量取决于缓存命中和调度情况。Q-outer 的价值需要同时考虑输出状态少读写、并行度增加和 KV 重读，不能仅凭循环交换判断总访存一定更少。[论文 §3.2](https://tridao.me/publications/flash2/flash2.pdf#page=8)

> FlashAttention-2 论文注明，交换循环顺序和沿 Query 序列维度并行的思路，最先由 Phil Tillet 在 Triton 实现中提出并实现。

> 长 KV 序列不一定带来足够的 Query 并行度。单 token decode 只有一个 Query，每个 Head 也就只有一个 Query Tile；官方实现后来针对这类场景增加了跨 Block 读取 KV、再合并结果的方案。[官方 2.2 更新记录](https://github.com/Dao-AILab/flash-attention#22-optimize-for-inference)

## Block 内按 Query 行分工

确定一个 Thread Block 负责哪个 Query Tile 后，还要决定其中的多个 Warp 如何协作。核心区别在于：让各 Warp 计算同一输出的部分贡献，还是分别完成不同的输出行。

**Sliced-K 将当前 Tile 的 Key/Value 分给不同 Warp。** 假设有 $W$ 个 Warp，且 Tile 的尺寸便于均分；第 $w$ 个 Warp 处理 $B_c/W$ 个 Key/Value，并为全部 $B_r$ 个 Query Row 生成一个 partial sum。用 $\widetilde P_{ij}^{(w)}$ 表示它负责的权重列，$V_j^{(w)}$ 表示对应的 Value 行：

$$C_{ij}^{(w)}=\widetilde P_{ij}^{(w)}V_j^{(w)}\in\mathbb{R}^{B_r\times d}$$

这些权重必须使用同一组逐行指数基准。它们是一个完整 Tile 的未归一化权重的不同列切片，各 Warp 不能各自归一化后直接相加。

所有 Warp 都在为同一组输出行提供贡献，因此需要把 partial sum 加起来：

$$C_{ij}=\sum_{w=0}^{W-1}C_{ij}^{(w)}$$

第一版实现通过 Shared Memory 写入中间结果、同步并读取归约，完成这一步。矩阵乘之外由此多出了中间结果读写和同步开销。

**Sliced-Q 将 Query Row 分给不同 Warp。** 各 Warp 都能访问当前 $K_j,V_j$，但只处理自己负责的 $B_r/W$ 行 Query，以及这些行的 Softmax 统计量和输出累加器。用 $(\widetilde P_{ij}')^{(w)}$ 表示这些行的权重，当前 Tile 的输出贡献为：

$$C_{ij}^{(w)}=(\widetilde P_{ij}')^{(w)}V_j\in\mathbb{R}^{(B_r/W)\times d}$$

不同 Warp 的结果对应不同输出行，可以各自更新自己的累加器，不需要跨 Warp 求和。

| 分工方式 | 每个 Warp 处理什么 | 生成的输出贡献 | 是否需要合并输出贡献 |
| --- | --- | --- | --- |
| Sliced-K | 全部 Query Row，部分 Key/Value | 同一组输出行的 partial sum | 需要跨 Warp 求和 |
| Sliced-Q | 部分 Query Row，当前 Tile 的全部 Key/Value | 互不重叠的输出行 | 各自更新，无需跨 Warp 求和 |

Sliced-Q 因而省去了合并输出贡献所需的 Shared Memory 读写和同步。这个结论针对输出归约；具体 kernel 为协作加载、使用或复用 Shared Memory，仍可能需要同步。[论文 §3.3](https://tridao.me/publications/flash2/flash2.pdf#page=9)
